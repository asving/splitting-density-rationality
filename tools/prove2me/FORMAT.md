# How the TypeDensity exporter rendered the tree

Each rule is marked **[verified]** (read off files; the evidence is named) or **[inferred]**.
These notes were written on 2026-11-11 before anything was compiled or uploaded, and the text below
is as it was then. What happened afterwards is in README.md: the bundle compiled against the
platform's files, the platform accepted every step, and the two points that section 8 leaves open
(the `attribute` line and the instance name) were settled.

Evidence

- Public export `prove2me/formalpedia`, commit `fd877e9f` (snapshot 2026-11-11), `envs/0df444a/`:
  all 36 `Definitions/Def_TypeDensity_*.lean`, 1034 `Theorems/Thm_TypeDensity_*.lean`,
  1035 `Solutions/Sol_TypeDensity_*.lean`, and the 1070 `TypeDensity` records of `index-*.jsonl`.
- Sources at tags `v1.1.0` and `v1.2.0`, read with `git archive`.
- Platform pages saved on 2026-11-11 (`thm_main_dvr.html`, `d_*.html`). The saved copies are not in
  this repository.
- A reproduction test: `build_bundle.py --selftest` regenerates the existing nodes from the
  v1.1.0 sources with the rules below and compares with the export. It reproduces byte for byte
  897 of 1033 statement files and 537 of 1033 solutions, among them every statement file of
  `Tests/NonVacuity.lean` (4), `Tests/Cluster.lean` (3) and `Cluster/Main.lean` (4), and all ten
  `TypeDensity.Expr.*` nodes. The misses come from constructs the three new files do not contain:
  file-local notation (the exporter expanded it), `noncomputable section`, `omit`/`include … in`,
  `open … in`, a repeated `set_option`, private definitions, and theorem dependencies reached by
  field notation.

## 1. What became what

| Source (v1.1.0) | Platform |
|---|---|
| module with non-private `def`/`abbrev`/`structure`/`instance` | one definition module `TypeDensity_<Dir>_<File>`; `Tests/X.lean` gives `TypeDensity_Tests_X` |
| public `theorem` | theorem node `TypeDensity.<name>` plus one solution (952 of 983) |
| public theorem cited by definition material | kept with its proof inside the definition module (31, e.g. `finite_field_irreducible_count` in `Def_TypeDensity_Formula_FiniteFieldCounts`) |
| private theorem used by one declaration | pasted into that solution; never a node |
| private theorem used by several declarations | a node under its own name (82) |
| private declaration needed by definition material | made public in the definition module (121) |

- **[verified]** `Tests/NonVacuity.lean` became three kinds of thing. `Def_TypeDensity_Tests_NonVacuity`
  holds only its eight instances. Its four public theorems are nodes `TypeDensity.Tests.*` with
  solutions. Its private lemma is pasted into `Sol_TypeDensity_Tests_isAdic_maximalIdeal_powerSeries`.
  The tree has 51 `TypeDensity.Tests.*` theorem nodes. A test file was not published as a
  definition module; only its definitions and instances were.
- **[verified]** `Cluster/Defs.lean` is `Def_TypeDensity_Cluster_Defs`, the whole file. `Cluster/Main.lean`
  has no definition module: four theorem nodes, and its three private lemmas pasted into
  `Sol_TypeDensity_main_dvr_cluster` (their only user).
- **[verified]** No definition module imports a `Theorems.Thm_*` module (all 36 import lists).

## 2. Renaming

- **[verified]** `SurfaceBlowup` becomes `TypeDensity` wherever it is a whole identifier component,
  docstrings included; `SurfaceBlowupV2` is left alone (`Def_TypeDensity_Basic`). `SurfaceBlowup/` is
  written `TypeDensity/` in `source` and in the generator comment; `Tests/` keeps its name.
- **[verified]** Names are otherwise unchanged: all 1034 node names are v1.1.0 names.
- **[verified]** Rejected names were not mapped. No node name has a character outside
  `[A-Za-z0-9_.]`; theorems with primes or subscripts stayed private helpers or sit in a
  definition module (`eval₂_C_X_eq_algebraMap`).
- **[verified]** Anonymous instances are written with a name: `instCommRingGenericClosure`,
  `instMeasurableSpacePowerSeries_tests` (18 instances). **[inferred]** That is the name Lean generates;
  `_tests` is added for an instance declared under `Tests` whose type mentions only Mathlib.

## 3. Definition module (`POST /submit-definition`)

```
-- Generated by the TypeDensity exporter from <path> (namespace TypeDensity); do not edit.
import Definitions.Def_TypeDensity_...
import Mathlib....
set_option autoImplicit false
<blank>
<the file's commands, one blank line between them>
```

- **[verified, 36 of 36]** `definition_title` is `Definitions of TypeDensity.Cluster.Defs`
  (`Definitions of Tests.NonVacuity` for a test file); the natural-language statement is the module
  docstring, renamed, line breaks and Markdown kept; the first line is the comment above.
- **[verified]** `source` is empty for all 36 (`null` in the index). Tags `["type-density"]` (`d_*.html`).
- **[verified]** Copyright header, module docstring, theorems that are nodes, private lemmas and
  `#print axioms` lines are removed.
- **[inferred]** The text ends with one newline.

## 4. Theorem statement (`POST /submit-problem`)

`preamble`:

```
import Definitions.Def_...
import Theorems.Thm_...
import Mathlib....
set_option autoImplicit false
<blank>
open TypeDensity                       (open TypeDensity TypeDensity.Tests in a test file)
<the file's open lines that are in scope, in order>
<the variable lines of the enclosing sections>
```

`formal_statement`: `theorem TypeDensity.<name> <binders> : <type> := by sorry`

- **[verified]** The preamble ends with one newline, the statement with none, and the stored file is
  `preamble + "\n" + formal_statement + "\n"` (bytes of `thm_main_dvr.html` against the export).
- **[verified, 1034 of 1034]** No generator comment; the statement starts with `theorem TypeDensity.`;
  no docstring, no attribute.
- **[verified]** The statement keeps the source text: only the declaration name is replaced by the
  full name, identifiers inside stay short.
- **[verified, 1034 of 1034]** The import list equals the solution's, theorem imports included. A
  statement can therefore be published only after the theorems its proof uses are Proved.
- **[verified]** `source` is `TypeDensity/Main.lean#L31-L51`, `Tests/NonVacuity.lean#L69-L88`: renamed
  path, first line of the docstring to last line of the proof (936 of 1034 agree with v1.1.0 line
  numbers; the rest are shifted by a constant per file). Tags `["type-density"]`.

## 5. Solution (`POST /verify`)

```
-- Generated by the TypeDensity exporter from <path> (namespace TypeDensity); do not edit.
<the same imports>
<blank>
set_option autoImplicit false
<blank>
[helper block]
open TypeDensity
[open TypeDensity.Expr]
<the same open and variable lines as the statement>
<blank>
theorem solution <binders> : <type> := <proof>
```

- **[verified, 1035 of 1035]** The uploaded file is exactly this text with one final newline: its
  SHA-256 is the one recorded in the index.
- **[verified]** Helper block: the source's `open`, `namespace`, `section` and `variable` commands up
  to the last helper, one blank line apart, the private lemmas verbatim with their docstrings, then
  the closing `end` lines (`Sol_TypeDensity_main_dvr_cluster`, `Sol_TypeDensity_two_chart_datum_concrete_instances`).
- **[verified]** In `theorem solution` references to project constants are written with their full
  name, pasted helpers included (`TypeDensity.hasPolynomialType_one_iff`).
- **[verified]** The exporter did not qualify every reference: `HasPolynomialType` inside set-builder
  notation stayed short in `Sol_TypeDensity_main_dvr_cluster`. **[inferred]** It qualified what its
  elaboration data reported. The bundle qualifies every reference found in the text. On the
  existing tree that rule never leaves short a name the exporter qualified (0 cases; it
  qualifies more in 22).
- **[verified, 10 of 10]** For a theorem named `TypeDensity.Expr.x` the solution has
  `open TypeDensity.Expr` after `open TypeDensity`; the statement file does not. Other prefixes
  differ (`LawSafe.`, `QCongr.` have no such line).

## 6. Import lists

- **[verified, 69 source files and 36 definition modules]** Definition imports: walk the source
  module's project imports depth first in file order and list each module that has a definition
  module when the walk leaves it; the file's own module last.
- **[verified, same]** Mathlib imports: the non-project imports met on that walk, each module's own
  after its project imports, without repeats.
- **[verified, 1034 of 1034]** Theorem imports are sorted by `(source path, first line)`; `Tests/`
  sorts before `TypeDensity/`. Order in the file: definitions, theorems, Mathlib.

## 7. Titles and natural-language statements

- **[verified, 1008 nodes with a docstring]** Title: the first paragraph of the docstring with its
  lines joined, cut after the first `.` or `;` that is followed by a space, then cut to 200
  characters. 931 titles are that sentence in full. 77 are cut short: 68 at 199 or 200 characters,
  often in mid-word, and 9 at 190 bytes (`main_dvr` among them); the bundle uses 200 characters.
  A leading `**Bold lead.**` does not end the sentence; `(resp. …` does
  (`TypeDensity.single_state_return_chain`).
- **[verified]** The 26 nodes without docstring have the short name with spaces as title.
- **[verified]** Statement: for 951 of 1008 it is the docstring, renamed, with the lines of each
  paragraph joined and paragraph breaks kept. The other 57 were reworded into full sentences
  (`Tests.main_dvr_galoisField`).
- **[verified]** No statement contains `$`. The tree uses backtick code spans, not KaTeX.

## 8. What in the new files has no precedent, and what the bundle does

1. `local instance` (`Tests/PadicInt.lean`). v1.1.0 has none. Statements of the file's theorems need
   the two local instances, and a `local instance` does not reach an importing file. The bundle keeps
   the definition module's text as in the source and adds one line to the preamble of the five
   theorems and their solutions:
   `attribute [local instance] TypeDensity.Tests.padicIntMeasurableSpace TypeDensity.Tests.padicIntBorelSpace`.
   Existing preambles contain only `open`, `variable`, `include`, `omit` and `set_option` lines, so
   whether the platform accepts an `attribute` line there is not known.
   `bundle/alt/padicint-as-module/` is the other reading: the whole file, theorems included, as one
   definition module that imports three theorems. It needs no new construct but no existing
   definition module imports a theorem, and the five theorems would not be nodes.
2. The explicit name `instFiniteResidueFieldPadicInt_tests` follows the pattern of
   `instFiniteResidueFieldPowerSeries_tests`; it was not checked against Lean.
3. The docstring of `universal_type_laws` has a bullet list (no theorem docstring had one); the list
   items are kept as Markdown list items.
4. The generator comment line is reused unchanged, although these files come from
   `build_bundle.py`.
5. Payloads carry `"env": "0df444a360eaa60ab8c11dca51a86af692955474"`. Whether the earlier upload
   sent `env` cannot be seen in the export; it pins the environment if the default moves.
